### 案例 001 · 判据是死代码，而它报的正是「全绿」

- **采集时点**：`2026-10-26T10:20:00Z`
- **适用场景**：某条判据一直报 PASS，且它是唯一约束某类事实的判据
- **前提**（执行前逐条核对，任一 ✗ 即判不可行）
  - [ ] 能定位该判据的**谓词表达式**（`文件:行号`）
  - [ ] 谓词用到的每个变量都能查到赋值处
  - [ ] 能构造一个「该判据应当报警」的注入
- **步骤**：
  1. 把谓词拆成每个变量的**求值路径**
  2. 对每个变量查 `Select-String -Pattern '\$var\s*='`——**找到赋值处**，确认它不在注释里
  3. 注入一个该判据应当抓到的错误，跑一遍
  4. **判据：注入后必须 FAIL**。仍 PASS ⇒ 死判据
- **结果**（真实经历）：`C6` 的 `$staleTotals` 赋值被上一行**行尾注释吞掉**，变量从未赋值；
  无 `Set-StrictMode` 时 `$null.Count` 恒为 `0` ⇒ 谓词退化 ⇒ 任何数字都对不出红。
  **它在失明期间一直报 PASS**，而同期文档里 `13+2+19+4+5+2=45` 与「共 46 格」并存。
- **已知边界**：本案例只覆盖「变量未赋值」。另一类是同形但更隐蔽的——变量被赋成了**恒真值**
  （如 `$x = $true`），需逐条看赋值右侧而不只是"有没有赋值"。
