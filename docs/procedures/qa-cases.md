# `qa` · 案例库（追加式）

> **本文件是案例，不是规范**。规范在 [`qa.md`](qa.md)；两者冲突时以 `qa.md` 为准。
> **平时不读**——只在 `qa.md` 的骨架覆盖不到当前情形、或需要照抄某次实测做法时读。

## 模式计数（达 3 次 ⇒ 标 `[待提升]`）

| 模式 | 次数 | 状态 |
| --- | --- | --- |
| 环境矩阵（维护者树 / 干净 clone / 最小初始化探针） | 1 | — |
| 注入五类（含「信号本身可被改掉」） | 1 | — |
| 守恒律（`PASS+FAIL+SKIP` 必须加得起来） | 1 | — |
| 事实可靠性三问（依赖什么 / 谁能改 / 改后变红还是变绿） | 1 | — |

> **怎么计数**：某模式被**实际用来抓到过缺陷**才 +1；只是"照着做了一遍没抓到"不计。
> 达 3 ⇒ 把状态改成 `[待提升]`，由总控在收尾时判断并入 `qa.md` 的哪一节。
> 提升后本表保留，并加一行「已提升至 `qa.md` §N」。

### 案例 001 · 用最小初始化探针复现「假红」与「硬崩」

- **采集时点**：`2026-10-26T09:00:00Z`
- **适用场景**：判据是**发给采用方的**，或判据引用了「本仓特有」的文件
- **前提**（执行前逐条核对，任一 ✗ 即判不可行）
  - [ ] `<仓库根>/docs/adopting.md` 存在且含「最小初始化」一节
  - [ ] `git` 在 PATH 上，且能 `git clone --no-hardlinks <repo> <dir>`
  - [ ] 被测脚本路径 `.claude/hooks/self-test.ps1` 存在
  - [ ] 能在 `$env:TEMP` 下建目录并 `git init`
- **步骤**：
  1. 建探针：按 `adopting.md` §二只复制 `launchers/` + `.claude/` + `AGENTS*` + `README*`
  2. `git -C <probe> init -q && git add -A && git commit -m init`
  3. 跑 `self-test.ps1`，记 `PASS/FAIL/SKIP`
  4. 逐项加回被采用的形态（装 `GEMINI.md` / 建进度页 / 装 `CLAUDE.md`）各跑一次
- **结果**（真实读数，`2026-10-26`）：
  - 原始形态 `35 / 5 / 5` → 其中 `C1 ONBOARDING` 与 `D4` 是**假红**（判据前提不成立）
  - 探针 + 自装 `GEMINI.md`：`36 / 4 / 5` —— 若用「`GEMINI.md` 存在 ⇔ 框架仓」当门，**假红原样复发**
  - 探针 + 建进度页：**硬崩** `DirectoryNotFoundException`，36 格后中止、**无小结**
  - 探针 + `CLAUDE.md` 含 `@ONBOARDING.md`：门若包住整格 `D4`，则该检查被**静默取消**
- **已知边界**：只覆盖 `adopting.md` §二列出的那几种文件；若采用方另装了索引里没有的文件，本案例不覆盖。

### 案例 002 · 「信号本身可被改掉」——验证判据不会由红转绿

- **采集时点**：`2026-10-26T09:05:00Z`
- **适用场景**：判据依赖某个**可被命令改动的状态**（索引 / 配置 / 标记文件 / 环境变量）
- **前提**（执行前逐条核对，任一 ✗ 即判不可行）
  - [ ] 能找到判据读取该事实的**那一行**（`文件:行号`）
  - [ ] 该事实有**至少一种命令**能改动它（如 `git rm --cached` / `git update-index`）
  - [ ] 有一个**干净 clone** 可用（避免污染工作树）
  - [ ] 改动可完全还原（`git reset` / 重新 clone）
- **步骤**：
  1. 在 clone 里跑基线，记读数
  2. 用命令改动那个事实（不动工作树文件本身）
  3. 重跑同一判据
  4. **判据：改动后必须仍然报警**。若由 FAIL 变 PASS ⇒ 该判据失明
- **结果**（真实读数）：
  - 依赖**当前索引**（`git ls-files`）：`git rm --cached` 后 `39 / 0 / 6`、**exit 0** ⇒ **由红转绿**
  - 改为依赖**提交历史**（`git rev-list --all`）：同一注入 `38 / 2 / 6`、exit 1 ⇒ 双 FAIL
- **已知边界**：只测了「索引」这一个事实。其他可改事实（配置文件、缓存、环境变量）需各自构造；
  本案例的方法可推广，但结论不可直接搬。

### 案例 003 · 守恒律核对：每个读数必须 `PASS+FAIL+SKIP = 总数`

- **采集时点**：`2026-10-26T09:10:00Z`
- **适用场景**：任何「N 格全绿」的声明；判据输出含三行小结时
- **前提**（执行前逐条核对，任一 ✗ 即判不可行）
  - [ ] 被测脚本输出含 `PASS = / FAIL = / SKIP =` 三行
  - [ ] 已知「总数」应是几（文档里抄写的值）
  - [ ] 能修改文档里的总数陈述以做注入
- **步骤**：
  1. 跑基线，抄下三行
  2. 三数相加，与文档里的总数比对
  3. 注入：把文档里任一处总数改成别的数
  4. 重跑，**必须 FAIL**
- **结果**（真实读数）：
  - 基线 `46 / 0 / 0`，和 = 46 ✓
  - 注入错误总数 ⇒ `FAIL C6（实际 46；文中出现 40/46）`、exit 1
  - **反例（`C6` 失明期间）**：同一注入仍 **PASS** —— 原因是 `$staleTotals` 的赋值被上一行行尾注释吞掉，
    变量从未赋值，`$null.Count` 恒为 0
- **已知边界**：`C6` 只看**总数**，看不出「少计 A、多计 B」的格级错配。
  要抓格级错配，必须逐个 SKIP 分支单独注入。

### 案例 004 · 事实可靠性三问（写判据之前做，不是之后）

- **采集时点**：`2026-10-26T09:15:00Z`
- **适用场景**：**新增或修改**任何判据之前
- **前提**（执行前逐条核对，任一 ✗ 即判不可行）
  - [ ] 已写下该判据**依赖的事实**（不是"它想测什么"，是"它读什么"）
  - [ ] 能列出**谁**能改掉那个事实（采用方 / 维护者 / 任意命令）
  - [ ] 能构造「改掉之后」的输入
- **步骤**：对每条判据回答三句，写进交付物：
  1. 依赖什么事实？
  2. 谁能改掉它？
  3. 改掉之后变红还是**变绿**？
  **变绿 = 洞**，改判据。
- **结果**（真实经历）：同一格修了**三版**才成立——

  | 版本 | 依赖的事实 | 谁能改 | 结果 |
  | --- | --- | --- | --- |
  | v1 | 某入口文件存在 | 采用方自己装 | 误判 → 假红 |
  | v2 | 当前索引 | `git rm --cached` | **由红转绿** |
  | v3 | 提交历史 | 无人 | 成立 |

  三问若在 v1 就做，可省掉两个版本。
- **已知边界**：它只能问出「可被改掉的事实」。「这个事实**是否足以代表**该判据要测的东西」
  （如 `GEMINI.md` 存在 ≠ 本仓是框架仓）是**另一类错误**，三问覆盖不到，需人工判断。
