| --- | --- | --- |

### 案例 001 · 五类注入各抓到一个真缺陷

- **采集时点**：`2026-10-26T10:30:00Z`
- **适用场景**：判据脚本改动后的独立负向验证
- **前提**（执行前逐条核对，任一 ✗ 即判不可行）
  - [ ] 被测判据脚本路径存在且可读
  - [ ] 有**还原手段**（备份文件或 `git checkout --`），每条注入后必须还原
  - [ ] 能在 `$env:TEMP` 下建副本，避免污染真实工作树
  - [ ] 被测脚本每次运行可接受（本例约 30 s / 次）
- **步骤**：对每条判据依次走五类；**每类跑完立即还原并核 `git status --porcelain` 为空**
- **结果**（真实读数）：

  | 类 | 注入 | 结果 |
  | --- | --- | --- |
  | 内容错 | README 总数改错 | `C6` FAIL ✔ |
  | 文件缺失 | 删 `ONBOARDING.en.md` | `C1` FAIL ✔ |
  | **文件变形** | `GEMINI.md` 做成目录 | **整脚本中止、无小结** ✘ |
  | **前提缺失** | 删 `docs/ledger.md` | **硬崩** ✘ |
  | **信号可被改掉** | `git rm --cached` | **由红转绿** ✘ |

  后三类是前两类覆盖不到的。
- **已知边界**：本案例的「信号可被改掉」只测了 git 索引。
  配置文件、缓存、环境变量属同类但需各自构造。

### 案例 002 · 让「未击穿」与「没测」可区分

- **采集时点**：`2026-10-26T10:35:00Z`
- **适用场景**：作为只读角色做静态分析，无 shell
- **前提**（执行前逐条核对，任一 ✗ 即判不可行）
  - [ ] 角色确实没有 shell（`tools` 仅 `Read`/`Grep`/`Glob`）
  - [ ] 能把「需实测」的项写成**可直接复制的命令**
  - [ ] 总控会回灌真实 stdout
- **步骤**：
  1. 每条结论**先标证据级别**
  2. 需要实测的，写进「待代跑命令清单」而不是猜一个结论
  3. 总控回灌后，把 `[未能验证]` 升级为 `[实测]` 并重判
- **结果**（真实经历）：静态分析报出 13 条攻击，总控代跑后确认 4 条成立。
  另有若干条经代跑**未击穿**——若当时把它们写成「应该会静默」，就会凭空造出缺陷。
- **已知边界**：静态分析能发现「结构上可能失明」，但**证不了**它是否真的静默；
  最后一步必须真跑。
