# `falsify` · 流程记忆

> **本文件是规则的应用形态，不是规则源**。与 `AGENTS.md` D3、
> `.claude/agents/falsifier.md` 冲突时，**以它们为准**（D4）。
> **角色文件回答「谁、能做什么、硬边界」；本文件回答「怎么攻击」**——两者不可互替。
> **平时不读**——只在需要对判据做负向验证时读。

---

## 一、何时用 / 何时不该用

**该用**：任何「失败即静默」的判据 / 门禁 / 断言；`AGENTS.md` §4.2 三跳链的第 2 跳。

**不该用**：实现方自写自验（D3：自己写的判据不得自己审）。

---

## 二、流程骨架

### 2.1 先问「它依赖什么事实」（**在做任何注入之前**）

对每条判据回答三句：

1. 它依赖什么**事实**？（文件存在 / 索引 / 历史 / 参数 / 环境变量）
2. **谁**能改掉那个事实？
3. 改掉之后判据变红还是**变绿**？

**变绿就是洞**。实测：跳过这一步会让同一格修三版（文件存在 → 索引 → 提交历史），
其中第二版能被 `git rm --cached` **由红转绿**。

### 2.2 五类注入（**缺一类就漏一族**）

| 类 | 例子 | 抓到的形态 |
| --- | --- | --- |
| **内容错** | 写错 SHA / 错总数 | 常规 |
| **文件缺失** | 删掉被测文件 | 常规 |
| **文件变形** | 做成**目录** / 空文件 / 带 BOM | 整脚本中止、无小结 |
| **前提缺失** | 删掉判据依赖的另一个文件 | 硬崩、中途中止 |
| **信号本身可被改掉** | `git rm --cached` 抹索引 | **由红转绿**（最严重） |

> **「删除」是最弱的一种**。只用删除验证「用消失来通过」，会漏掉后三类。

### 2.3 每条必须给「注入 → 期望 → 实际」

格式：

```
判据原文 → 注入故障的确切命令 → 期望观察到的失败信号 → 实际是否如期 [证据级别]
```

### 2.4 证据级别（**不得含糊**）

- `[实测]`——依据**总控回灌的真实 stdout**
- `[静态读代码]`——只读了代码，没跑
- `[未能验证]`——需要但拿不到的证据

> **`[静态读代码] 未击穿` 与 `[实测] 未击穿` 不是同一个结论。**

## 三、高价值靶子（真实发生过）

| 靶子 | 形态 |
| --- | --- |
| **空分母** | 覆盖率脚本在空分母报告上打印 `branches 100%` |
| **`try/catch` 不捕获** | 目标地址无代码 ⇒ 类型化调用打在空地址上静默 revert |
| **口径混用** | 用 `find` 而非 `git ls-files` ⇒ 把构建产物算进统计 |
| **行尾差异** | 覆盖率阈值按 CRLF 本机标定 ⇒ CI 的 LF 读数偏低 |
| **`@` 导入静默失败** | `@中文目录/ascii.md` 静默失败；`@ascii目录/中文.md` 成功 |
| **判据自身失明** | 变量未赋值 / 谓词退化 ⇒ 任何输入都 PASS |
| **依赖事实可被改掉** | 索引可被 `git rm --cached` 抹空 |

---

## 四、输出契约

1. **攻击清单**：判据 → 注入命令 → 期望失败信号 → 判定（会静默 / 不会 / 无法判定）+ **证据级别**。
2. **需总控代跑的命令清单**：分组、可直接复制、每条说明验证哪一条攻击。
3. **P0/P1/P2 排序**：哪些是「判据实际失明」，哪些只是文档不一致。
4. **一句话裁决**：这套判据还有没有牙。

> **未击穿也要报**，并说明试过哪些攻击——**不要为交差编造缺陷**。

## 六、升级条件

- 攻击发现的问题需要**改规则源** ⇒ 上交总控。

## 七、提升阈值

同一攻击模式出现 **3** 次 ⇒ 标 `[待提升]`；由总控并入本文件。
