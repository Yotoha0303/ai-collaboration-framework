# `qa` · 流程记忆

> **本文件是规则的应用形态，不是规则源**。与 `AGENTS.md` 冲突时一律以它为准（D4）。
> **平时不读**——只在要执行 `qa` 流程时读。**不被任何入口 `@` 导入**。
> 角色定义见 `.claude/agents/qa-validator.md`；本文件讲的是**怎么测**，角色文件讲的是**谁、能做什么**。

---

## 一、何时用 / 何时不该用

**该用**：
- 需要回答「**这条判据是否真有牙**」——即：它在**该报警的输入**上会不会报警。
- 03 测试环；对任一 PR 做**独立于实现方**的测试。
- 改动涉及**判据脚本 / 守卫 / 门禁**时（规则类改动没有运行时症状，只能靠注入发现）。

**不该用**：
- 纯文档措辞修订，且不触碰任何判据（用 `C3`/`C6` 这类结构格即可）。
- 实现方自测——那**不是** 03 环准出（`AGENTS.md` §4.2），不要用本流程替代独立测试。

## 二、输入契约

| 项 | 为什么必须有 |
| --- | --- |
| **被审对象是哪个 commit** | 工作树有未提交改动时，读数**不对应任何版本**，不可复现。先确认工作树干净或记下 diff。 |
| **适用对象**：框架模板 / 采用方 | 十环门禁只约束采用方；本仓是模板，判「不适用」而非「未通过」（`AGENTS.md` §2 适用对象段）。 |
| **该判据声称要测什么** | 不知道它声称测什么，就无法设计「该报警」的输入。 |

## 三、流程骨架（四类追问，按顺序）

### 3.1 环境矩阵 —— 判据在「谁身上跑」不同，结论就不同

| 环境 | 它回答什么 |
| --- | --- |
| 维护者树 | 作者环境是否绿（基线） |
| 干净 `git clone` | 读者能否复现；**绿是否依赖未入库的运行态** |
| **按文档最小初始化的工作区** | 采用方照文档做会怎样 |
| 其他运行时入口（若有） | 换一个入口是否仍成立 |

> **实测依据（`2026-10-26`）**：3 个 P0/P1 **全部**来自换工作区形态，而不是读代码。
> 其中「按文档最小初始化」抓到：采用方建进度页后**硬崩**、Antigravity 采用方**假红复发**、
> `@` 导入检查**被整格关掉**。

### 3.2 注入矩阵 —— 五类，缺一类就漏一族

| 方式 | 例子 | 实测抓到过 |
| --- | --- | --- |
| 内容错 | 写错 SHA / 错总数 | 常规 |
| 文件缺失 | 删掉被测文件 | 常规 |
| **文件变形** | 把文件做成**目录** / 空文件 / 带 BOM | 整脚本中止、无小结 |
| **前提缺失** | 删掉判据依赖的另一个文件 | 硬崩、36 格后中止 |
| **信号本身可被改掉** | `git rm --cached` 抹索引 | **由红转绿**（最严重） |

> **「删除」是最弱的一种**。不能只用删除来验证「用消失来通过」是否被挡住。

### 3.3 守恒律 —— 每条读数必须能加得起来

`PASS + FAIL + SKIP = 已知总数`。任一行加不起来 ⇒ 它是在不同格数下采集的，**不能放进同一张表**。

> **实测依据**：`C6` 死掉期间，文档里 `13+2+19+4+5+2=45` 与「共 46 格」并存而无人发现。

### 3.4 事实可靠性 —— 一行就能省掉整个版本

对**每条**判据问三句：

1. 它依赖什么**事实**？（文件存在 / 索引 / 历史 / 参数 …）
2. **谁**能改掉那个事实？
3. 改掉之后判据变红还是**变绿**？

**变绿就是洞**。实测：同一格修了三版才成立——

| 版本 | 依赖的事实 | 谁能改 | 结果 |
| --- | --- | --- | --- |
| v1 | 某入口文件存在 | 采用方自己装 | 误判 → 假红 |
| v2 | 当前索引 | `git rm --cached` | **由红转绿** |
| v3 | 提交历史 | 无人 | 成立 |

## 四、输出契约

按 `AGENTS.md` §3 五段交付，且必须含：

1. **用例清单**：编号 · 命令 · 期望 · **实测** `PASS/FAIL/SKIP` + exit。
2. **缺陷分级**：P0（判据实际失明 / 整脚本中止）· P1（检查被静默取消 / 假红复发）· P2（文档不一致 / 空分母）。
3. **阻断裁定**：**可提交 / 不可原样提交**，一句话理由。
4. **环境标注**：每个读数是哪个环境、哪个 commit 采的。

---

## 五、升级条件

必须上交总控（不在本流程内自行决定）：
- 发现的问题**需要改规则源**（`AGENTS.md` / `prompts/` / 角色契约）——那是元架构变更。
- 判据的取舍涉及**误报 vs 漏报的价值判断**（例：行内 `@` 算不算导入）。
- 修法**会改变对采用方的判定**（例：加「角色数 > 0」前提会让零角色的采用方整体变红）。

提升后**案例保留**，加一行「已提升至 `<file>` §N」。**3 是可改常数，改它需人裁定。**
