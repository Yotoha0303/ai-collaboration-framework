### 案例 001 · 文档里引用了「总数」样例，把 `C6` 自己搞红了`已提升至 ledger-sync.md §2.7`

- **采集时点**：`2026-10-26T10:40:00Z`
- **适用场景**：写判据文档、变更记录、台账留痕时，**引用了格数 / 总数的样例**
- **前提**（执行前逐条核对，任一 ✗ 即判不可行）
  - [ ] 被测仓库有 `C6` 一类「扫描总数陈述」的判据
  - [ ] 能读到该判据的**识别模式**（`self-test.ps1` 的 `$totalPatterns`）
  - [ ] 能跑一次 `self-test.ps1`
- **步骤**：
  1. 写文档前先看 `$totalPatterns` 的各条正则
  2. 引用样例数字时，**改写措辞**使其不匹配（例：把「共 N 格」改成「总数 N」）
  3. 写完立刻跑一次 `self-test.ps1`
  4. 若 `C6` 报「文中出现 X/Y」，**先怀疑自己刚写的那句**
- **结果**（真实经历，**发生三次**——第三次在 `2026-10-26` 推广到 `gate-audit-cases` / `ledger-sync-cases` 时再次触发）：
  - 第一次：`guard-self-test.md` 把探针读数按「通过数 / 失败数」的斜杠形态写上——命中该模式，
    基线从 `45 PASS` 掉到 `44 PASS / 1 FAIL`
  - 第二次：`docs/procedures/qa.md` 复述历史总数——命中该模式，`C6` 立刻报「文中出现 48/46」
- **已知边界**：这是「判据文档与被判据文档是同一批文件」的结构性张力，**无法根治**。
  只能靠「写完就跑一次」这条纪律。

### 案例 002 · 台账插入位置错了两次

- **采集时点**：`2026-10-26T10:45:00Z`
- **适用场景**：用脚本往台账表格中间插入新行
- **前提**（执行前逐条核对，任一 ✗ 即判不可行）
  - [ ] 台账是**表格**（`|` 分隔），且新增行必须落在表内
  - [ ] 能 `Select-String` 定位锚点行号
  - [ ] 插入后能跑 `C3`（表格列数一致）
- **步骤**：
  1. 先 `Select-String` 打印**锚点前后各 3 行**，确认它在表内而不是表头
  2. 用「找到锚点 → 在它之后插入」的方式，**不要**用「删掉若干行再拼回」
  3. 插入后立刻跑 `self-test.ps1`，看 `C3` 与 `E1`
- **结果**（真实经历）：
  - 第一次插到了**表头**（`| 项 | 值 |` 与 `| 已用 INC- |` 之间）——`C3` 报表格列数不一致
  - 第二次用「删 3 行」的方式挪位置，**把 `| 已用 INC- |` 那行一起删掉了**
  - 两次都是脚本跑完就"看起来成功"，只有跑 `self-test` 才发现
- **已知边界**：本案例针对 markdown 表格。若台账将来改成其他格式，锚点策略需重定。
