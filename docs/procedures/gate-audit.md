# `gate-audit` · 流程记忆

> **本文件是规则的应用形态，不是规则源**。与 `AGENTS.md` §2 门禁矩阵、
> `.claude/agents/gate-auditor.md` 冲突时，**以它们为准**（D4）。
> **角色文件回答「谁、能做什么、硬边界」；本文件回答「怎么裁」**——两者不可互替。
> **平时不读**——只在需要转段裁决时读。

---

## 一、何时用 / 何时不该用

**该用**：阶段收尾要进入下一阶段；或需要判定「准出是否真正满足」。

**不该用**：
- 仍在同一阶段内做子任务（`AGENTS.md` §4.2：**同阶段内的子任务不是阶段推进**）。
- 实现方自审——**自己写的判据不得自己审**（D3），必须由本流程的执行方做。

---

## 二、流程骨架

### 2.1 先判「适用对象」——**这一步在逐环核验之前**

| 对象 | 十环门禁 | 依据 |
| --- | --- | --- |
| **框架仓（模板）** | **不适用**（04/06–10 无对应物属模板性质） | `AGENTS.md` §2「适用对象」段 |
| **采用方（业务项目仓）** | **全部适用**；对应物不存在 ⇒ 判「未满足」**并阻断**，**不是「不适用」** | 同上 |

> **判据一句话**：`git rev-parse --show-toplevel` 一次即可分辨。
> **但这不等于"框架仓就什么都免了"**：模板仓**仍受 D1–D4 与机械守卫约束**，
> 免除的**只是十环流水线门禁**。

### 2.2 定位「当前环 → 目标环」

读 `AGENTS.md` §2 的准出条件，逐条列**前置环的硬资产**。

### 2.3 逐条核验：三态，**没有第四态**

每条给出：**证据（命令 + 真实输出）· 判定（满足 / 不满足 / 无法判定）**。

> **`无法判定` 不是"大概率没问题"**。它专指「我没有那个证据」。
> 判据一句话：**「没跑到」**与**「跑了说没问题」不是同一个判定**。

**只读角色没有 shell（常态，不是条件）** ⇒ 把待实测项列成**命令清单**交总控代跑，
回灌 stdout 后再判分。**未回灌的一律 `无法判定`。**

**不得**用「读代码看起来对」充当「准出满足」（D2 默认怀疑）。

### 2.4 结论：三选一

- **放行**
- **阻断**——必须附**解除条件**（每条可执行）
- **无法判定**——必须附**缺哪份证据**

## 三、高价值核查点（真实踩过）

| 项 | 易错点 |
| --- | --- |
| **覆盖率阈值** | 必须看**配置文件实际值**；CRLF 与 LF 检出读数不同，**不得据旧记录判"未配"** |
| **04 构建环** | 采用方：无 Dockerfile / 无 `REVISION == HEAD` 断言 ⇒ **判未满足并阻断**。**不得**因"CI 绿了"当作满足 |
| **`gitignore` 类声明** | 用 `git check-ignore -v --no-index <path>`；**已入库的文件不会命中**（即使规则本应忽略它）——别误判为"规则没问题" |
| **框架文件位置** | `AGENTS.md` / `record.md` / `.claude/` 在**工作区根**；**不得**当作"仓库里丢了文件" |

---

## 四、输出契约

1. **准入审查**：本阶段是哪一环 · 前置资产是否满足 · **适用对象是哪个**。
2. **裁决表**：维度 · 放行/阻断/无法判定 · 依据（`文件:行号` 或条文）。
3. **阻断项清单**：每条附**解除条件**。
4. **需总控代跑的命令清单**（若为只读角色）。
