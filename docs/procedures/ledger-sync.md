## 一、何时用 / 何时不该用

**该用**：新增 `GAP-` / `DEFER-` 编号 · 写 `docs/changes/NNN-*.md` · 同步台账与页面投影 · 收尾。

**不该用**：**用户待办不进台账**（`AGENTS.md` §6 边界）——它们的源是用户自己的清单，不是台账。

---

## 二、流程骨架

### 2.1 登记新编号前：**跨全部 ref 取并集**

```
git for-each-ref --format='%(refname)' refs/heads refs/remotes
# 对每个 ref：git ls-tree -r --name-only <ref> -- docs/changes/
```

> **不要用 `git log --all --name-only`**——它默认简化 merge，由 merge 引入的文件不会出现，
> 并集**少算**，于是取到已被占用的号（实测踩过）。

**判据**：取到的号在**所有 ref** 上都不存在。只看当前 HEAD 是**假守卫**。

### 2.2 登记前：全仓检索确认未被覆盖

```
git grep -n '<关键词>' -- .
```

**与既有编号撞车比漏登记更糟**（D4）。若已有一条覆盖同一根因，**并入它的同族成员，不另开号**
（先例：`GAP-017` 的同族成员明确写了「不另开号」）。

### 2.3 写台账行（四列）

| 列 | 要求 |
| --- | --- |
| 编号 | 升序、不复用、不重号 |
| 缺口（一句话） | 说清**是什么**，不是**为什么严重** |
| 证据 | **可复跑的命令 + 真实读数**；不是"已测试" |
| 解除条件 / 状态 | 解除条件必须**可执行**；状态取值只有 `未解除` / `已解除` / `待人工裁定` |

> **解除时改状态并加一行留痕，不删原条目**（`AGENTS.md` §5 历史快照不改写）。

### 2.4 足迹锚 `docs/changes/NNN-*.md`

**先写后填**：改动落地前先立记录，落地后回填实测结果。**禁止事后补写当成"先写"**。

### 2.5 三处投影必须同成熟度（**最容易漏**）

| 处 | 记什么 | 更新方式 |
| --- | --- | --- |
| `record.md` | **发生了什么**（命令级留痕） | **追加，不删不改既有行** |
| `memory.md` | **现在是什么状态** | **覆盖式** |
| **进度页 HTML** | **给人看的当前进展** | **覆盖式** |

**只更一个 = 两处不同成熟度的事实**（D4）。进度页由 Stop hook 机械保障（它只比对主干 SHA，
**不检查内容是否一致**——内容同步仍靠人）。

> ⚠️ **页面的「④ 质量缺口」组是台账的投影**。台账新增编号而未更页面 ⇒ `E1` 会 FAIL。
> 反之，页面写了台账没有的编号 ⇒ 无人检查（已知边界）。
