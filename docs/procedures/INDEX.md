# 流程记忆 · 索引（按需读）

> **本目录是什么**：一组「**平时不读、执行某流程时才读**」的规范及其案例库。
> 用途有二：① 让流程有稳定的书面规范；② 把大文件里的流程知识拆出来，降低常驻上下文。
>
> **本目录不是规则源**。与 `AGENTS.md` 冲突时**一律以 `AGENTS.md` 为准**（D4）。
> 本目录**不被任何入口 `@` 导入**——那会让它变常驻，与本机制的目的相反。
>
> 设计依据：issue **#61**（机制）· 首个实例：issue **#62**（`qa`）。

> **新增流程**：在本表加一行，并建同名 `<流程>.md` 与 `<流程>-cases.md`。
> `INDEX.md` **不得**复述任何规范正文——它只做路由。**超过 40 行即视为失控**。

## 二、怎么用（四步）

1. **进来**：按上表选流程，读它的 `.md`。
2. **照做**：按其中的骨架执行。
3. **不够用**：读对应的 `-cases.md`，逐条核对案例的**前提**；
   全 ✓ 才可执行，任一 ✗ 即判「不可行」→ 转**案例设计**。
   **核对结果必须写进 `record.md`**（不留痕时「核对过」与「没核对」在观测上同形）。
4. **收尾**：若某模式在案例库里出现 **3** 次，标 `[待提升]`，由总控判断并入 `.md` 的哪一节。
   提升后**案例保留**，加一行「已提升至 `<file>` §N」。

## 三、两个模板（新建流程时照抄）

### 3.1 流程记忆文件 `<流程>.md`

```markdown
# <流程> · 流程记忆
> 本文件是规则的应用形态，**不是规则源**；与 `AGENTS.md` 冲突时以它为准（D4）。

## 何时用 / 何时不该用
## 输入契约
## 流程骨架
## 输出契约
## 升级条件
## 案例库指针 → `<流程>-cases.md`
## 提升阈值：同一模式出现 3 次 ⇒ 标 `[待提升]`
```

### 3.2 案例（写进 `<流程>-cases.md`）

```markdown
### 案例 NNN · <一句话>
- **采集时点**：YYYY-MM-DDTHH:MM:SSZ
- **前提**（执行前逐条核对，任一 ✗ 即判不可行）
  - [ ] `<路径>` 存在
  - [ ] `<脚本>` 支持 `<参数>`
- **步骤**：可照抄的命令
- **结果**：**真实读数**，不是预期
- **已知边界**：它不覆盖什么
```

> ⚠️ **前提必须是可机械核对的形态**（路径存在 / 参数存在 / 命令可用）。
> 写成「确保环境正确」这类无法判真假的句子，会让第 3 步退化为走过场——
> 而走过场的检查比没有检查更糟（D3）。
