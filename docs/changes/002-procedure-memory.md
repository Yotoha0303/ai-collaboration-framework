## 一、为什么要改

用户提出一个可复用于任意流程的抽象机制：

> 执行流程 P → 读 P 的**记忆文件**（平时不读）→ 按其中的规范执行 →
> 规范不够则读**案例库** → 案例前提成立就照做，否则先做**案例设计** →
> 完成后，高频模式**提升进记忆文件**，其余仅留在案例库。

它同时解决两件事：**流程规范化** 与 **静态文件上下文过大**。
本仓 `AGENTS.md` 已达 **65.1 KiB**，正是后者的活样本。

## 三、三个设计点（用户 `2026-10-26` 已裁定）

1. **存储形态**：`docs/procedures/`，索引 + 每流程一个记忆文件 + 一个案例库。
   入口**只指向 `INDEX.md`**——否则「按需」立刻变「常驻」。
2. **案例可行性**：**前提清单 + 留痕**。案例格式强制含 `- [ ]` 行（可机械核对）；
   执行前逐条核对，结果写进 `record.md`；任一 ✗ 即判不可行 → 转案例设计。
3. **提升回路**：同一模式出现 **3** 次 ⇒ 标 `[待提升]`；总控收尾时判断并入哪一节；
   提升后**案例保留**并加「已提升至 `<file>` §N」。
