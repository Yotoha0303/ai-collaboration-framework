## 八、执行事故与纠正（如实登记，**不改写**）

**事故**：本轮为隔离改动，我用 `git switch -c docs/adr-002-parallel-subagents` **切了分支**。但本工作树当时**还有另一个并行会话**在跑（`ai-collaboration-framework-29`，M0 线）——切分支把**它也一起带到了我的分支上**。

**后果（实测）**：该会话随后往 `docs/ledger.md` 写入 `GAP-047`（进度页 BOM 致守卫静默失明）与 `GAP-048`（双标记方向依赖），**与我的 `GAP-047` 撞号**——两行并存于同一张表。它是在**我的分支**上写的，若我不恢复，它的未提交工作会随我的分支一起离开，而它自己不会知道。

**纠正**：

1. `git stash` 保存它的台账改动 → `git switch` 回 `feat/aicf-guard-m0` → `merge --ff-only docs/adr-002-parallel-subagents`（把我已提交的 `cb84e11` 快进进来）→ `stash pop` 恢复它的改动。**分支位置与工作树均回到它原本的样子**。
2. **我让号**：`GAP-047`/`048` 归它（先到先得），我的改为 **`GAP-049`**，全部引用同步（`AGENTS.md` ×2 · `AGENTS.en.md` ×2 · ADR-002 ×4 · 本单 ×6 · 台账 ×2）。
3. 它**仍不知情**——`ListAgents` 显示其 `busy`，`SendMessage` 本轮不可用。

**这正是 `ADR-002` §2.2「跨链临界区」的活教材**：规则写了「任何跨链写操作一次只允许一条链做」，而我**在写下它的同一轮里**做了相反的事（切分支是**工作树级**写操作，比文件写更高一层，而规则只点名了「提交 / 改台账 / 改 `memory.md` / 改 `docs/changes`」）。

⇒ **应补进 ADR 的口径**：临界区**必须包含「切分支 / 改 HEAD」**——它影响的不是某个文件，而是**同工作树内所有会话的上下文**。归 **`GAP-049`** 的残余（本单**不再自行扩权**，先留证）。
