## 2. 决策（Decision）

四条决策 + 三组「三选一」。**每条都给出可证伪的判据**（D3）。

### 2.1 【#70】「铺满」的作用域 = **单个父会话内、且限于「并行桶」**

**定义**：

- **并行桶（parallel bucket）** = 同一生命周期阶段内、**彼此无输入输出依赖**、且**不产生转段结论**的一组子任务。
- **链（chain）** = 一条完整的「阶段 → 转段三跳（`qa-validator` → `falsifier` → `gate-auditor`）→ 下一阶段」推进路径。
- 一个父会话内可同时存在**多条链**，但**每条链内部严格串行**（`DEFER-013` 冻结）。

**铺满规则**：

1. 桶内**按上限铺满**；**取 3**（= `§4.0` 现有上限，**不新增上限**）；
2. **桶内角色去重合并**：同一角色在桶内**只派 1 个实例**，多个子任务合并在它的提示词里 —— 「同一角色的 N 个并行实例」不在本条支持范围内（§5 Q4）；
3. **跨链临界区（`§2.2`）合计也不超过 3**；
4. 桶内任一子任务失败 ⇒ **该桶整体不算产出**，修复后重跑桶，**不"部分推进"**。

> ⚠️ **为什么优先「多链」而不是「同阶段多桶」**：同阶段多桶（如 A 做支付、B 做登录）**技术上也能切**，但两者的产出**同时**进 01 环评审时，`gate-auditor` 无法回答「当前在第几环」——D2 的裁决会退化成**两个互相矛盾的放行**。故**本 ADR 优先多链**；同阶段多桶**允许，但每桶必须自带独立的 01 资产**（各自的 ADR 节 + 验收标准），否则不构成桶。

### 2.2 【#70-Q2】并发上限的**计数单位** = 每父会话同时「在飞」的角色实例

**定义**：**在飞（in-flight）** = 已派发、尚未回报的子代理。计数单位 = **父会话级全局**，不是每阶段、也不是每链。

**跨链的「在飞合计 ≤ 3」由临界区强制**：任何跨链写操作（提交 / 改台账 / 改 `memory.md` / 改 `docs/changes`）**一次只允许一条链做**；未持锁的链**只能读**。

**为什么是父会话级而不是全局**：多窗口 / 跨会话的**总并发**属于 #11 的运行时编排（`§7` 划界），**本 ADR 不裁**。

### 2.3 【#72】任务代号 = `T-<YYYYMMDD>-<slug>`

| 维度 | 决定 | 理由 |
| --- | --- | --- |
| 形态 | `T-20261028-parallel-dispatch` | `T-` 前缀**不与** `GAP-`/`DEFER-`/`ADR-`/`MIG-`/`INC-` 混淆（`AGENTS.md:628-664` §6） |
| 不用序号 | `T-001` **禁止** | 序号 = 又造一个**跨分支共享计数器**，正是 `§6.1`（`AGENTS.md:696-718`）已实测证伪三次的坑 |
| 日期作用 | 提供**自校验**的唯一性下界 | 同日同 slug 撞的概率低；**不需要全局登记处** |
| slug | 小写 ASCII + 连字符，≤ 40 字符 | 无中文，避免 `@path` 遇中文目录静默失败（`AGENTS.md:63`） |
| 生命周期 | 任务收尾即**可删** | 见 §2.5 |

### 2.4 【#72-Q2/Q3】可见锚 = **`docs/changes/NNN-<task-slug>.md`**，代号进**文件名**

**决定**：代号**必须**先出现在仓内一个**入库**的变更单文件名里：

```
docs/changes/006-parallel-dispatch.md      ← 变更单（入库）
        └── 正文首行写 `任务代号：T-20261028-parallel-dispatch`
```

**为什么是文件名而不是标题**：`check-numbers.ps1:204` **只看路径**（§1.4）⇒ 代号进**文件名**即可**复用既有跨分支可见性**，**不新增脚本**。进标题则必须改脚本（读正文），而该脚本刻意「不用 `git log`、只看树」（`check-numbers.ps1:182-183` 的注释）——**改它等于破它的设计**。

**为什么是 `docs/changes` 而不是 `record.md`**：`record.md` **不入库**（`.gitignore` 首条）⇒ 代号挂在那里**跨分支不可见**，等于没挂。

**代号与 `docs/changes` 编号的关系**：`006` 是**变更单编号**（`§6` 唯一编号空间），`T-…` 是**协作目录名**（临时）。两者**不同层**，允许一单对多任务、或一任务跨多单。

### 2.5 【#71】协作目录的形态

**位置与命名**：

```
<工作区根>/.collab/<任务代号>/<子代理名>.md    # 每个子代理一份，只追加
<工作区根>/.collab/<任务代号>/_index.md       # 派发清单；只有总控能写
<工作区根>/.collab/<任务代号>/README.md       # 一页声明；派发时生成
```

**六条硬约束**：

| # | 约束 | 判据 |
| --- | --- | --- |
| C1 | **粒度为「一子代理一文件」**，不共用一份 | 共用一份 ⇒ 并发写同一文件 ⇒ D4「两处不同成熟度」同族 |
| C2 | **写方角色只追加自己的文件**；`_index.md` **只有总控能写** | 与 `record.md`「追加式不删」（`AGENTS.md:422-431`）同构 |
| C3 | **只读角色（`falsifier` / `gate-auditor`）不破例**，写权**不授予** | 破它会让 `self-test.ps1` 的 `F1` 格变红（`AGENTS.md:371-380`「只读角色不得带 shell / `Write` / `Edit`」）；**代写责任**见 §2.6 |
| C4 | **目录根部 `README.md` 必须声明**「非事实源 / 不进 commit / 结论须回写 `docs/changes` 与台账」 | 这是 D4 的物理面；**无此行 ⇒ 该目录不得创建** |
| C5 | **排除规则进 `.gitignore`**（随仓库分发），**规则带前导 `/`** | 见 §2.7 |
| C6 | **任务收尾可删**；删除判据 = 变更单已成文 + 目录内无「开放」项 | 可机械检查（两文件齐 ⇒ 可删） |

### 2.6 【#71-Q2】只读角色的共享记忆 = **只读 + 总控代写**

**决定**：

1. `falsifier` / `gate-auditor` **只能读** `.collab/<任务代号>/`，**不获得写权**；
2. 它们的产出**由总控代写**进 `.collab/<任务代号>/<角色名>.md`，**并在文件首行标注**：

   ```
   > 代写：本文件由总控按 <角色名> 的回报誊录；原文见本轮交付回复。
   ```

3. **它们读到的他人文件是「事实」还是「传闻」，必须显式标注**：`.collab/` 里**其他角色的文件**对只读角色而言是**未验证输入**，不得作为裁决证据（`§2` 门禁矩阵的准出证据须来自仓库实测或命令 stdout）。

> **这是本 ADR 最重要的一条边界**：`.collab/` 是**草稿**，不是证据。把它当证据 = 用「别人写在纸上的话」替代「自己跑出来的 stdout」，正是 `falsifier` 这个角色存在要防的事。

### 2.7 【#71-Q3】排除规则进 `.gitignore`（**含一条风险与对策**）

**决定**：在 `.gitignore` 追加

```gitignore
# 并行子代理协作草稿（ADR-002 §2.5）：运行态，不是交付物。
# 规则带前导 `/`（锚定仓根，理由同 /memory.md）。
/.collab/
```

**风险（如实登记）**：`AGENTS.md:797-807`（§9.1）要求「**本机排除规则的内容不得携带**」——那是针对 `.git/info/exclude` 的**个人条目**（如某个业务仓目录名）。`.collab/` 是**框架机制的一部分**（每个采用方都会用），性质是**框架源**而非**个人条目** ⇒ 可入库。**两者的判据不同**：问「它从框架来，还是从上一个项目来？」——`.collab/` 来自框架。

**若用户不愿改 `.gitignore`**：退路是只写 `info/exclude`，并在 `ONBOARDING.md` 加一句「采用方需自行忽略 `.collab/`」。**代价**：采用方漏做即一次 `git add -A` 入库（`.env.local` 的同类事故有过先例，`.gitignore:19-24`）。**本 ADR 推荐 `.gitignore`**。

### 2.8 【#72-Q4】`T-` **不进** `§6` 标识符表

**决定**：`T-` 是**协作目录名的约定**，**不是标识符类别**。理由：`§6` 的 5 类（`ADR-`/`MIG-`/`GAP-`/`INC-`/`DEFER-`）全部是**必须登记、必须长期可追溯**的；`T-` 恰好相反——**任务收尾即消失**。把它写进 `§6` 会让「必须登记」的语义被稀释。

## 3. 三组「三选一」的裁断（决策分派①，逐条可否决）

| 问题 | 选项 | **裁断** | 理由 |
| --- | --- | --- | --- |
| **#71-Q1** 目录形态 | ① `<任务代号>/<子代理名>.md`　② `<任务代号>-<子代理名>/` | **①** | ② 让**清理**变成「删 N 个目录」且**任务边界不可见**；① 一个任务一个目录，`README.md` + `_index.md` 有地方放 |
| **#71-Q2** 只读角色写权 | ① 不破例，总控代写　② 给限定路径写权 | **①** | ② 破 `F1` 机械不变量；且「只读」的价值正是**不能自己写结论** |
| **#71-Q3** 排除层 | ① `.gitignore`　② `info/exclude` | **①** | 见 §2.7；② 让采用方漏配即入库 |
| **#71-Q4** 目录要不要守卫 | ① 建　② 不建 | **②（延期）** | 归 `GAP-049`，与 `PreToolUse` 并行守卫**同批**做；现在建一个只查「`.collab/` 未被 `git ls-files` 收录」的守卫**价值低**（`.gitignore` 已挡住），而真正的风险（**草稿被当证据**，§2.6）**它查不出** |
| **#70-Q1** 铺满作用域 | ① 仅桶内　② 放开跨阶段 | **①** | ② 即进入 D2 判定区，属 `§4.0` 硬边界 1 明写的「不是决策，是违规」 |
| **#70-Q3** 要不要机械判据 | ① 建　② 纯提示词 | **①（登记 + 延后接入）** | 判据已设计（§6.3），但接入要在 `GAP-017` 同族的 `PreToolUse` 批次里，**本 ADR 只出规格、不接 hook**——否则会在 `.claude/settings.json` 里留一个**没见过真实流量的**守卫 |
| **#72-Q1** 代号形态 | ① `T-<YYYYMMDD>-<slug>`　② `任务-NNN` | **①** | ② 再造跨分支计数器（§2.3） |
| **#72-Q2** 可见锚 | ① `docs/changes` 文件名　② 标题　③ `record.md` | **①** | 见 §2.4；`record.md` 不入库，**跨分支不可见** |
| **#72-Q3** 复用 `check-numbers` | ① 复用（代号进文件名）　② 改脚本读标题 | **①** | ② 破该脚本「只看树」的设计（`check-numbers.ps1:182-183`） |

## 4. 替代方案（Options）与权衡

### Option A —— 本 ADR（桶内铺满 + 仓外草稿目录 + 文件名锚）· **推荐**

- **优点**：不新增编号空间、不破只读不变量、不改任何现有守卫。
- **缺点**：**跨分支的 `.collab/` 互不可见**，同日同名任务的草稿会混（§5 R3）。

### Option B —— 协作目录入库（当作交付物）

- **否决理由**：它是**逐轮变化的过程草稿**，入库即产生「过程记录 × 交付记录」两份副本（D4）；且会让 `check-numbers` 的扫描面扩张。

### Option C —— 序号制任务号（`T-001`）+ 全局登记处

- **否决理由**：登记处本身需要**跨分支同步**，而同步点又是「谁先提交谁赢」——**把 `§6.1` 的坑原样搬过来**。

### Option D —— 不做协作目录，全靠总控上下文转发

- **否决理由**：N 个并行子代理的产出全挤在总控上下文 = 直接撞 issue #17 的「长会话注意力稀释」。**这是诉求本身要解决的问题**，不能作为选项被否掉。

## 6. 验收标准（Acceptance Criteria，可测）

### 6.1 01 环准出（本 ADR 自身）

| # | 判据 | 命令 | 期望 |
| --- | --- | --- | --- |
| A1 | 编号不撞车 | §1.5 的逐 ref `ls-tree` 并集 | `docs/adr/` 只多出 `ADR-002`；`docs/changes/` 只多出 `006` |

### 6.3 【#70-Q3】并行守卫的**规格**（本 ADR 只出规格）

**形态**：`PreToolUse` hook（Claude Code，`.claude/settings.json`）+ Antigravity 侧经 `stop-adapter.ps1` 同构。

**它拦什么**：

1. **计数**：本会话内 `Agent` 工具调用中，**已派发未回报**的条数 ≥ 3 时，拦截第 4 条；
2. **跨链临界区**：同时存在 ≥2 条链时，任一**写操作**（`Write`/`Edit`/`Bash` 中的 `git commit`）若该链未持锁，拦截；
3. **只读角色破例**：`falsifier`/`gate-auditor` 调用 `Write`/`Edit` ⇒ 拦截（**须考虑**「总控代写」如何与它区分——**否，代写是总控自己在写，角色未变**）。

**负向验证（D3，必跑）**：注入第 4 个 `Agent` 调用 ⇒ **必须 block**；`falsifier` 调用 `Write` ⇒ **必须 block**。只验「≤3 时静默」**不足以**证明它有牙。

**已知难点（如实）**：`PreToolUse` 拿得到 `tool_name` 与 `tool_input`，但**「已派发未回报」这个状态跨工具调用累积**，hook 是**无状态**的单次进程 ⇒ 需要落一个 `.collab/` 之外的**计数器文件**，而它又成了新的运行态。**这是接入前必须解决的第一个问题**，故本 ADR **不接**。
