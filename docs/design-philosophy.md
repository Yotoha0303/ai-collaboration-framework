一句话版本（本文归纳）：

> **不从「AI 该怎么写代码」出发，而从「AI 在哪里会静默地错」出发**——
> 每次静默的错都换一条**机械判据**；判据本身再用**负向用例**守住；
> 由此沉淀出**单一事实源、布局无关、可证伪、角色分工**四条主线，外加**决策分派**与**注意力预算**两条工程约束。

**术语（本文沿用，不新造）**：**判据** = 能被证伪的断言 · **守卫** = 执行判据的进程 · **尺子** = 验证守卫还有没有牙的自测 · **投影** = 同一事实给人看的副本 · **锚** = 计划（`docs/planning/`）与足迹（`docs/changes/`）· **咬合力** = 判据在多大程度上不依赖模型自觉 · **参照系** = 用来判断「够不够成熟」的外部标准 · **回路** = 「经验 → 规范」的按次提升机制。

### 2.1 把 P1–P12 压成三句话

1. **事实层**：说不准的就不说（P1），说了的就要留痕（P11 的 `record.md`）。
2. **结构层**：一处事实一处源（P4 / P5），判据之间不许互相借绿（P6 / P7），共享空间按并集算（P10）。
3. **执行层**：该停的停、该走的走（P12），每一步都要能被人核对（P1 / P3）。
