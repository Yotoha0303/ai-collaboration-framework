## 一、提交前本地门禁（**本地跑的那一套 = CI 跑的那一套**）

**判据**：**"提交前先跑一遍"如果不能在本机跑出来，它就不是门禁，只是一句提醒**。
故：把 CI 的检查项在本机也固化成一串可复制的命令，按技术栈分 Gate；**过不去就不提交**
（与 §5「破提交不得进入 git 历史」同源）。

**形态（按栈分 Gate，示例取自真实生产仓）**：

```bash
# Gate 1：前端 / TS 全套
pnpm type:lint && pnpm test && pnpm build

# Gate 2：合约 + 数学一致性套件
cd contracts && npx tsc --noEmit && npx hardhat test --coverage && npx tsx scripts/check-coverage.ts

# Gate 3：高并发后端
cd ../backend && go vet ./... && go test -race ./...
```

**三条可泛化要求**（与具体技术栈无关）：

1. **同一套**：本地 Gate 与 CI 矩阵**是同一批检查**。两边不一致就会出现"本机绿、CI 红"，
   而那种红**不携带信息**——它分不清是**代码错**还是**环境差**，于是每次都得人去看，**门禁就退化成了噪声**。
2. **`--race` / 竞态检测不是可选项**：并发正确性**只有**竞态检测器看得见。
   `go test` 不带 `--race` 时**全绿也可能是错的**——这是"判据看起来在测、其实没测到"的又一形态（`AGENTS.md` §8）。
3. **缺前置就失败，不静默跳过**：Gate 要**显式断言前置条件**（依赖装没装、凭据在不在、服务起没起）。
   **缺前置时直接失败**——静默跳过会让"没跑"看起来像"跑过了"（D3：失败即静默的判据最危险）。

> **与 §4.2 的关系**：§4.2 管**阶段之间**的推进（测试环 → 证伪 → 裁决）；
> 本节管**同一次提交之前**的那道闸。**两者不可互替**：§4.2 过了不等于本地 Gate 过了。

## 二、待执行指令类文档（**只能由人或外部平台做**的那些事）

**问题**：交付链里总有一批事**AI 协同方做不了**——在 GitHub / 云平台面板 / 链上水龙头 / DNS 控制台补的
**密钥、分支保护 required check、域名白名单、平台侧环境变量**。这类事**必须显式单列**，
否则它们**不在任何台账里、也没人认领**，最后表现为"功能做完了但联调不通"。

**四条硬要求**：

1. **单列一份文档**（如 `docs/CICD-待完成.md`），**不混进台账的 `GAP-`**。
   它**不在 `GAP-` 台账里不代表它不存在**——它是**另一类**未竟事项：**欠的不是代码，是外部动作**。
   > ⚠️ **与 §6 的关系**：§6 说"不在台账里的『还没做』等于不存在"。本条是对它的**边界补充**：
   > **"外部动作"类**同样不能不存在，但它**不占用 `GAP-` 编号**（避免台账里混进"AI 做不了"的项，
   > 让人误以为可以派活）。
2. **性质声明写在文件头**：**它是「待执行指令」，不是历史记录**——故**必须与仓库实测一致**（D1/D4）；
   与实测不符时**以实测为准并更新它**。
   > **判据**：本节与 §5 的「历史快照不改写」**正好相反**——那条说"已发生的事实不需要准"，
   > 这条说"**待执行的指令必须准**"。**区分二者的判据是"它是已发生的还是待做的"**。
3. **每行只答三件事**：**缺什么 · 在哪补（哪个平台/面板） · 谁做**。
   `谁做` 只有两种取值：**人**（外部后台）或**平台**（自动完成）。
   **没有一条是 AI 能代办的**——写明这一点，是为了**避免 AI 反复尝试去"配"它配不了的东西**。
4. **标阻塞关系，并把阻塞项单独抽引**（放在文件顶部）：
   每行标**是否阻塞当前可交付款**；`阻塞=否` **不等于**「不必做」，只等于「现在不做也能跑」。
   **这个区分必须显式写出来**，否则会被读成"可不做"。

> ⚠️ **同时要列「实测确认不需要配」的项**：否则总有人去配一堆**多余的 secret**（真实生产里踩过）。
> **"不列已配好的、却单列确认不需要的"**——这两个相反的取舍**要一起写清**，才不会被误读成遗漏。

## 三、双语结构核对（`GAP-022` 的复跑命令）

**问题**：`README` / `AGENTS` 声明「英文是**同一规则源的语言投影**」（D4），
但**"投影"此前没有机械判据** —— 实测就漏了：`AGENTS.en.md` 曾**缺 `§4.2` 的正文**（只有指向它的引用）
与**整节 `§6.1`**。**只读英文的读者会以为框架没有这两条规则。**

**核对（两条，都要跑）**：

```powershell
# ① 章节数必须相等
(Select-String AGENTS.md    -Pattern '^#{2,3} ').Count
(Select-String AGENTS.en.md -Pattern '^#{2,3} ').Count
# 期望：两个数相等。不等 ⇒ 投影漏了节。

# ② 逐节【层级】必须一一对应（# 的个数），并列出首个错位点
$zh = (Select-String AGENTS.md    -Pattern '^#{2,3} ').Line
$en = (Select-String AGENTS.en.md -Pattern '^#{2,3} ').Line
for ($i=0; $i -lt [Math]::Min($zh.Count,$en.Count); $i++) {
  $a = ([regex]::Match($zh[$i],'^#+')).Value.Length
  $b = ([regex]::Match($en[$i],'^#+')).Value.Length
  if ($a -ne $b) { "第 $i 节 层级 zh=$a en=$b  zh: $($zh[$i])  en: $($en[$i])" }
}
# 期望：无输出。
```

> ⚠️ **这两条只查"结构"，查不了"内容是否等价"** —— 两版都有的节，正文可能仍有出入。
> **本轮实测**：修前 zh **30** 节 / en **28** 节（错位自 `§4.2` 起）；补齐后 **30 = 30**，逐节层级全对齐。
> **判据已建**：`C1`（章节数）+ `C2`（判据词双语在场，4 锚点）——见本节 §一之二。
>
> ⚠️ **盲区比上面这句自认的更宽——`2026-10-14` 由 `qa-validator` 注入实测推翻其乐观边界**：
> 对 `AGENTS.en.md` 注入 ① `all three must hold` → `any one may hold`（**判据从合取变析取**）；
> ② **整条删除**硬边界「`Not an exemption`」。结果：两条命令**全绿**（`30=30`、错位 `0`），
> 连"新节命中数"也全绿。**即：硬判据的 AND/OR 反转与整条边界消失，都测不出。**
> **结论（回答"这证明什么"）**：凡基于**标题 / 计数 / 命中数**的核对，只能证明「**东西在那儿**」，
> **证明不了「东西是对的」**。
> **`C2` 即为此设的最小机械判据**（要求中英两侧的判据词各自在场）——**但它只收窄盲区，不等于内容等价**：
> 它判的是「判据词在场」，**不判次数相等、不判语义未被反转**。该边界已写进 `C2` 的注释与本节。
