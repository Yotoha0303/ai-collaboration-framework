| 案例 | 发现 | 证据 | 教训 |
| --- | --- | --- | --- |
| **ignore 锚定** | `.gitignore` 的 `ignition/deployments/` **带内部斜杠且无前导 `**/`**，是**根锚定**模式 → 只匹配仓库根的 `ignition/`，**从未命中**子目录下的同类路径。多份部署产物（含 `deployed_addresses.json`）已被误提交 | `git check-ignore -v --no-index <path>` → **exit=1**；`git ls-files` 显示已入库 | **`check-ignore` 对已入库文件恒返回 1，必须加 `--no-index` 才可信**。否则会把它误判成"规则没问题" |
| **幻影路径** | 多份**活跃**文档指向一个**并不存在**的文件（真实文件名在另一目录）。四份文档、一份源码注释全错 | `git grep -n "<幻影路径>"` → 活跃文档命中；改指后清零 | 框架建立时才发现，而此前**每个读到它的人都会以为那是真的** |
| **覆盖率口径** | 覆盖率地板按**CRLF 本机读数**标定 → CI 的 LF 检出偏低，**首跑即红**。同一份源码、同一编译器、同一测试 | 两个检出各自跑覆盖率，对比同一指标 | **行尾是测量口径的一部分**，不是编辑器偏好。本项目后加 `.gitattributes` 强制归一 |
| **编号撞车** | 把一个早已被审计报告覆盖的问题**误登记为新编号** | 全仓 `git grep` 后发现既有编号已覆盖 | **登记前必须先检索**——撞车比漏登记更糟（见 D4） |
| **测试全绿 ≠ 被测覆盖** | 一份"看起来在保护某财务公式"的对拍测试，源码里**刻意把被测参数设为 0**——该公式**从未被验证**。只跑一遍测试看到全绿的人**不会知道这里有洞** | 读源码注释 + 读记录文件自述，才发现 | **"测试全绿"不等于"被测的东西被覆盖了"** |
| **两道门只跑一道会漏** | 同一公式有**两道独立**判据（一道吃源码、一道吃**向量文件**）。证伪时只变异源码不重生成向量，**另一侧仍然绿** | 变异测试实测 | **验证必须同时跑两道**；"跑了一道绿了"不构成证据 |
| **判据随事实变迁漂移** | §5 曾用「框架在仓库外，故位置保障其不可能入库」论证框架不入库。而本仓**就是**框架自身的仓——论证的**前提已不存在**，文字却照旧。 | `git rev-parse --show-toplevel` → 工作区根；`git ls-files` 含 `AGENTS.md` / `CLAUDE.md` / `prompts/*` / `.claude/*`；`Test-Path .gitignore` → `False` | **自指陈述不会被任何测试发现**——它说的不是代码行为，而是**它自己所在的位置**。与下条同族：错的不会响，只会静默地错。 |
| **工具名被静默丢弃** | `tools:` 名单里的工具名与**实际挂载名**不一致时**被静默丢弃，不报错**。`.claude/agents/*.md` 原写 `Bash`，而本机挂载名是 **`PowerShell`** → `Bash` 被丢 → 只读角色**看起来"没有 shell 能力"**。由此**误诊**为"本环境不挂载 Bash"，并把该误诊**写进了规则源**（本次修正已改写该处） | 派子代理**自报工具清单** + 跑 `Get-Location; echo probe-ok` 回灌 stdout → 工具清单 = `Read/Grep/Glob/PowerShell`，`probe-ok`，`LASTEXITCODE=0` | **声明的能力必须实测**——`tools:` 是**声明**，挂载才是**事实**。「**名字写错**」与「**能力缺失**」在观测上**不可分**；失败**无声**，故**不会被任何测试发现**。核验方法见 `.claude/agents/README.md` |

### 追加（`2026-10-12`）

| 案例 | 发现 | 证据 | 教训 |
| --- | --- | --- | --- |
| **语言投影会漏规则，而没有任何判据会发现** | 两版都声明「英文是**同一规则源的语言投影**」（D4）。实测：`AGENTS.en.md` **缺 `§4.2` 的正文**（只有 6 处**指向它的引用**——指向英文里不存在的节）与**整节 `§6.1`**。**只读英文的读者会以为框架没有这两条规则。** 中文 **30** 节 / 英文 **28** 节 | 章节枚举对照 `Select-String '^#{2,3} '` 得 30 vs 28；关键词 `6\.1` / `cross-branch` / `ls-tree` 在英文版**命中 0**（台账 `GAP-022`） | **"同一规则源的语言投影"是一个会被违反的断言，不是一句声明。** 投影**必须逐节核对结构**（章节数 + 逐节层级），而**内容等价目前仍无机械判据**（只能人工）——**这一条是"投影"这个说法自带的缺口**，与"同一份事实两处副本"（D4）同源 |
| **"能跑通" ≠ "判据正确"** | 一个 Stop 守卫**每次都能跑、每次都静默**，于是被当作"没问题"。实测它**从未拿到过同族的结构性修复**（缺 `Invoke-GitChecked` 收拢、缺负向金丝雀），且**只扫子目录 ⇒ 在自托管布局下 0 候选、直接放行、从不检查本仓**。更早还查出**大小写键塌陷**（真撞车静默）与**枚举失败塌进"无候选"** | 台账 `GAP-019` / `GAP-020`；对照另一守卫：`Invoke-GitChecked` **10** vs **0**、金丝雀 **5** vs **0** | **"跑得动"与"判据成立"是两件事，且前者会被后者冒充。** 对 fail-closed 判据，**唯一能分开二者的办法是负向用例**——而"它没吭声"在两种情形下**完全同形**（同 `GAP-002`）。**发现路径本身值得记**：这条是**另一角色越出作用域报的**，不是自查出来的 |
