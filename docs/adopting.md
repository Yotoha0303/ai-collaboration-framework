## 一、门禁的"语言插槽"：框架只管卡点，判据由你插

**这是本框架可插拔的关键一句**：十环门禁**约束的是状态机**——
「这一环有没有准出物、准出物是否可测」。**具体用什么命令去测，是插槽里的东西**，
按你的技术栈填。框架**不绑定 Go、不绑定 TS、不绑定任何 CI**。

| 环 | 卡点（框架固定，`AGENTS.md` §2） | 插槽：判据（**按栈填**） |
| --- | --- | --- |
| **01 设计** | ADR 落盘 + 验收标准**可测** | 无固定命令——ADR 是文档；"可测"指验收标准写成 Given-When-Then 之类**可判真假**的形式 |
| **03 测试** | 新用例 **100% 纳入 CI 矩阵** + 覆盖率**配置阈值** | **Go 栈**：`go vet ./... && go test -race ./...`（`-race` **不是可选项**）· **前端栈**：`pnpm type:lint && pnpm test && pnpm build`，覆盖率阈值读 `vitest.config` **实际配置值** |
| **04 构建** | 镜像**不可变 Digest** + 运行时断言 `REVISION == Git HEAD` | 容器栈：`docker buildx build --provenance` + 启动时断言；**非容器栈**这条要么有等价物，要么**该环判未满足**——**不是"不适用"** |
| **05 部署** | 脚本**全链路幂等**（连续跑两次无状态突变） | 同一份部署脚本**连跑两次**，比对第二次前后的状态哈希 |
| **10 自动化** | 定时器**前置条件断言** + **独立归档报告** | 定时任务里**显式断言**依赖（依赖装没装、凭据在不在）；**缺前置直接失败，不静默跳过** |

> 📄 **可照抄的三道 Gate 命令形态**见 [`delivery-gates.md`](delivery-gates.md)（按需读）；
> **十环各环在真实生产仓里的参照实现**见 [`reference-implementations.md`](reference-implementations.md)（按需读）。
> 两份都是**参照，不是规则源**。

⚠️ **别把"我的栈没有这个对应物"读成"这一环不适用"**：对应物不存在时该环判
**「未满足」**（该建而未建），**不是「不适用」**。这条口径是本框架从一次**误判**里收窄出来的。

## 二、最小初始化脚手架（三步）

> **三步都在你的新工作区里做，做完即可从工作区根启动。** 完整清单见 `AGENTS.md` §0.0。

1. **复制启动器与 `.claude/`**——把 `launchers/` 与 `.claude/` 整个目录搬到你的工作区根。
   `.claude/` 必须在**会话启动时已存在**才会被加载；中途新增/移动要 `/hooks` 重载或重启会话。
2. **配置 `.claude/progress-page.txt`**——**一行**，写你的进度页文件名。
   页名唯一事实源就是这一行：**改名 = 改这一行**，脚本与文档都不用动。
   页名先随便定也行——页面不存在时守卫**静默放行**（判据的前提是"页面存在且不得落后"）。
3. **在 `AGENTS.md` 里填项目专有内容**——`AGENTS.md` §0 位置约定（你的仓库根怎么解析）、
   §7 基线（当场实测的数字与复核命令）、§8 漂移示例（换成你自己的踩坑记录）。
   **框架与项目解耦**：这三处是**可替换的实例**，不是框架的不变量。

> **第 4 件（不算"三步"里，但别省）**：把**运行态三件**挡在提交之外——
> 用**随仓库分发**的 `.gitignore` 只排 `record.md` / `memory.md` / 进度页；
> **不得**排交付物与框架源。判据：**它是"项目的交付物"，还是"AI 自己怎么干活的"？**

## 三、采用前的项目化清单

框架本身与具体项目**解耦**——`AGENTS.md` 里凡是项目专属的部分（仓库路径、实证基线数字、
缺口台账）都是**可替换的实例**，不是框架的不变量。

采用时：

1. **把 `AGENTS.md` 放到你的启动目录**，逐节替换项目专属内容
   （`AGENTS.md` §0 位置约定、§7 基线、§8 漂移示例）。
   本框架统一用 `project/` 作**仓库子目录的占位名**，按实际改名即可。
   **但别把占位名当判据**：仓库由**含 `.git`** 识别，**名字任意**——
   **不得**凭"有没有一个叫 `project` 的目录"判定项目是否存在或缺失。
   解析仓库根用 `git rev-parse --show-toplevel`；工作区根**自身含 `.git`** 时，
   仓库**即工作区根**（此时没有 `project/` 子目录，是正常布局）。
2. **按注册表实例化你需要的角色**到 `.claude/agents/`。
   **只实例化你会派发的**；未实例化的角色**当前不可派发**，
   需要时**新建**，**不得**拿现有的顶替。
   本框架附带的 `falsifier` / `gate-auditor` / `ssot-scribe` 可直接沿用。
3. **保留 D3 与那个 hook 的负向用例**。机制里最容易被砍掉的就是这两样，
   而被砍掉之后系统**看不出来**少了什么。
   自测脚本见 [`guard-self-test.md`](guard-self-test.md)。
4. **运行态三件**（`record.md` / `memory.md` / 进度页）**不要入库**——
   判据一句话：**它是"项目的交付物"，还是"AI 自己怎么干活的"？** 只有前者入库。
