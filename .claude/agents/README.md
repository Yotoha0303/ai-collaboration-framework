# .claude/agents/ — 执行 Agent 层（角色契约的**实现**层）

本目录是 `prompts/AI协同工程架构.png` 中**「执行 Agent 层（并行 Agent 群）」**的落地。

- **角色契约是三层，本目录只是第三层**：
  | 层 | 文件 | 作用 |
  | --- | --- | --- |
  | 模板 | `prompts/角色契约.md` | 一个角色该写的 **9 项**（使命/责任范围/输入条件/工作流程/决策权限/输出契约/验收标准/升级条件/评价指标） |
  | 注册表 | `prompts/角色契约.md` | **有哪些角色** + 各自**输入/输出契约**（总控**派发前必查**） |
  | 实现 | 本目录 `*.md` | 本项目**已实例化**的角色：作用域 / 硬边界 / 铁律 / `tools` 白名单 |
- 角色表、边界与协同纪律的**权威定义在 `AGENTS.md` §4**（含**并发 ≤3**、注册制、成对互审等硬约束）。
- ⚠️ **路径基准（布局无关）**：子代理 CWD 是**工作区根**；**仓库 = 含 `.git` 的那个目录，名字任意**
  （见 `AGENTS.md` §0.0）。故本目录各文件写作用域时**不得写死目录名**：
  用**仓库根**表述（"仓库内 `docs/**`"），有 shell 时用 `git rev-parse --show-toplevel` 解析。
  `project/` 只是**占位名**——工作区根**自身含 `.git`** 时，仓库**即工作区根**，
  此时不存在 `project/` 子目录，**是正常布局**，**不得**据其有无判定项目存在或缺失。
  **不得**在仓库内该放交付物的位置之外乱建目录；**也不得**因占位名对不上就以为框架坏了。
- 每个 `*.md` 的 YAML frontmatter（`name` / `description` / `tools` / `model`）由 Claude Code 加载；
  正文即该子代理的 system prompt。
- 只读角色（如 `falsifier` / `gate-auditor`）的 `tools` **仅 `Read` / `Grep` / `Glob`**——
  **不含 `Write` / `Edit`，也不含任何 shell**。这是**机械只读**（本框架的裁定：保留机械只读，
  代价是**执行交总控代跑**，见 `AGENTS.md` §4 协同纪律）。
  - ⚠️ **不得把「不含 Write/Edit」当作只读的判据**——那是**判据夹缝**：
    **shell 是写后门**，`Set-Content` / `Out-File` / `Remove-Item` 都能落盘、能删文件，
    只挡 `Write` / `Edit` **挡不住它**。形态同 `AGENTS.md` §8「两道门只跑一道会漏」。
  - **代价（显式，不是降级）**：只读角色**无法执行命令**，故其**执行一律由总控代跑**——
    它们产出**攻击清单 / 裁决表 + 需代跑的命令清单**，总控跑完回灌**真实 stdout** 后再据实判分。
- ⚠️ **`tools:` 里的工具名必须与本机实际挂载名一致**——解析不了会被**静默丢弃、不报错**，
  与"能力缺失"**外观完全相同**。本机（Windows）实测挂载名是 **`PowerShell`**，不是 `Bash`
  （框架建立时曾据 `Bash` 被丢弃**误诊**为"本环境没有 shell"）。**修法因角色而异**：
  **写方**（如 `ssot-scribe`）只列**本机实测名**，换机（macOS/Linux 为 `Bash`）时按实测改；
  **只读方**（`falsifier` / `gate-auditor`）**任何 shell 都不列**——它们要的就是"没有 shell"，
  列上即开写后门。**核验方法（可复跑）**：派一个子代理，令其**自报工具的确切名字**
  并跑最小命令回灌 stdout（`Get-Location; echo probe-ok`）——出现 `probe-ok` 与 `LASTEXITCODE=0`
  才算该会话**确实有 shell**。**`tools:` 是声明，挂载才是事实**；两者不一致时**无声**。
- 子代理**严禁擅自修改 `memory.md`**（注册表硬约束）——由总控统一沉淀。
- 本文件无 frontmatter，会被加载器按文档跳过（预期行为，勿加 frontmatter）。
- **本目录现有两类实现**（`AGENTS.md` §4.1）：
  ① **业务角色 10 类**——注册表角色各自的**基础契约**（`biz-strategist` … `rca-investigator`），
     覆盖全生命周期，**按需深化领域角色**（如 web3 的 `contract-dev`，见台账 `DEFER-006`）；
  ② **纪律执行者 3 类**——`ssot-scribe`（D4）· `gate-auditor`（D2，只读）· `falsifier`（D3，只读），
     不在注册表 10 类之内。
  **第 ① 类尚未实测其工具挂载**——首次派发前按上文核验方法跑一次（`tools:` 是**声明**，挂载才是**事实**）。
- ⚠️ **新建/改名的角色需重启会话才被加载**（与 `.claude/` 的其他改动同一口径：加载器只在会话启动时扫描本目录）。
