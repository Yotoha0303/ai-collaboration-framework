# 进度页滞后守卫（`check-progress.ps1`）— 实现细节

> **本文件是 `AGENTS.md` §5「进度页同步」的**实现细节**部分，按需读取。**
> 该节只留**判据与约定**（常驻）；此处的**五处设计 / 静默分支 / 平台理由 / 加载时机**移到这里，
> 以便**单文件体量可控**（用户待办第 7 条）。
> **规则的权威源仍是 `AGENTS.md` §5**——本文件与它冲突时以 §5 为准（D4）。

## 判据（与 §5 同文，此处复述以便单文件自足）

**仅当进度页存在时**，才把页面状态条记录 `<div>head <b>…</b></div>` 里的 SHA
与 `git -C "$REPO" rev-parse --short HEAD`（`$REPO` 见 `AGENTS.md` §0.0）**按前缀比对**
（页面写 7 位或 40 位皆可）；不一致则**阻断本轮结束**并把原因回灌给模型，要求先更新页面。
**页面不存在时无判据可言**——见下方第 1 条。

## 五处刻意的设计

1. **页面不存在时不检查**——页面尚未建立时守卫**静默放行**（`exit 0`，无输出）。
   判据的前提是「**页面存在且不得落后于仓库**」；页面不存在时**没有可滞后的事实**。
   **这是"尚未初始化"，不是"页面丢了"**——与 `AGENTS.md` §5「首次使用即初始化」同一口径。
2. **指针存在却读不出页名 → `exit 1` + stderr**（空文件 / 全为空白 / 不可读）。
   此时守卫会回退到默认页名，**可能在看一个错误的文件**——这是**真异常**，
   故告知用户而非静默；指针文件**整个缺失**则不算异常（同第 1 条）。
   **`git` 不可用**（功能探针 `git --version` 失败）**走同一通道**。
   **为何不用 `systemMessage`**：它只进 `Ctrl+O` 转录视图、不进主终端（本机实测用户未见）；
   `exit 1`（非零、非 2）是**文档保证**的「非阻断错误」，转录里可见。
3. **找不到 SHA 标记时静默**——页面被改结构到认不出时，报警不如不报（避免每次都误报）。
4. **不同步就阻断，而不是提醒**——**提醒会被忽略，阻断不会**。
5. **页名走指针文件**——页面会随进度改名；若把页名写死在脚本里，一次改名就会让它**静默失效**。

## 验证：必须跑两个用例（D3）

> ⚠️ **这些分支使脚本"失败即无声"**：路径或页名推导一旦写错，它会**永远静默放行**，
> 而"静默"正是它正常时的表现。脚本因而**同时兼容两种布局**（`.claude/` 在工作区根，或回退到仓库内），
> 验证**必须跑两个用例**：① **缺页** → 静默 `exit 0`；② **注入错误 SHA**（页面**存在**）→
> **必须 emit `decision:block`**。
> **只有 ② 仍有牙，才能反推 ① 的静默是"确无判据"，而不是"脚本死了"**——二者在观测上等价。
> **改页名后务必重跑这两个用例。**
> **已接受的代价**：指针写错（**指向一个不存在的页名**）时守卫仍静默——它与"尚未初始化"不可分；
> 残余风险见台账 `GAP-002`。

可复跑的命令见：`docs/ledger-evidence/ledger-appendix-c.md` 的 **C.2**。

## 平台与加载（两条实测踩过的坑）

> ⚠️ **为什么是 PowerShell 而不是 bash**：若 Git for Windows 装在某个使 `usr/bin`
> **不在 Windows PATH** 上的位置，hook 写 `bash …` 在 Windows 执行时**必然失败**，
> 而 `System32\WindowsPowerShell` **在 PATH 上**。**命令里刻意不含任何反斜杠**——
> 反斜杠经 shell 转义被咬掉过两次，改用正斜杠路径后消失。
> 编辑该文件请用编辑器，不要用 shell heredoc。

> ⚠️ **hook 需在会话启动时已存在才加载**：settings 监听器只监视**会话启动时已有 `.claude/` 的目录**。
> 若在会话中途新增/移动了 `.claude/`，**需打开一次 `/hooks` 重载，或重启会话**——
> **当会话内不要指望它**。任何涉及 `.claude/` 位置的改动，都**需在下一会话才生效**。
